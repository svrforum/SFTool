# 실물 검증 체크리스트

CI 러너에는 USB가 없다. 그래서 **쓰기 경로의 최종 확인은 자동화할 수 없고**,
실제 Windows PC에서 사람이 해야 한다. 이 문서는 그때 빠뜨리기 쉬운 것들을 모은 것이다.

자동으로 검증되는 범위는 `README.md`를 참고할 것. 여기 적힌 항목은 **전부 수동**이다.

## 준비물

- Windows 10 (1903 이상) 또는 Windows 11
- 8GB 이상 USB 저장장치 (지워도 되는 것). **복제(7절)를 시험하려면 두 개**가 필요하다
- 가능하면 **내장 디스크가 여러 개인 PC** — 안전 규칙을 시험하려면 필요하다
- 있으면 좋은 것: USB 외장 SSD, 카드리더, 쓰기 방지 스위치가 있는 USB

## 1. 장치 목록 — 가장 중요한 부분

되돌릴 수 없는 작업이므로 여기서 틀리면 사용자의 데이터가 사라진다.

- [ ] **내장 디스크(C:, 데이터 HDD, NVMe)가 목록에 하나도 보이지 않는다**
- [ ] USB를 꽂으면 목록에 나타난다
- [ ] 장치 이름이 실제 제품명과 비슷하게 보인다 (빈칸이 아니다)
- [ ] 용량이 USB에 적힌 숫자와 비슷하다 (32GB USB → 30GB 대)
- [ ] 드라이브 문자가 표시된다
- [ ] **USB 외장 SSD/HDD**를 꽂으면 목록에 나타난다
      (이것들은 removable=false로 보고하므로, 안 보이면 버스 타입 판정이 잘못된 것)
- [ ] **카드가 없는 카드리더**는 목록에 나타나지 않는다
- [ ] 카드를 넣으면 나타난다
- [ ] 4GB USB는 보이되 **"용량이 부족합니다"와 함께 선택 불가**로 표시된다
      (숨겨지면 안 된다 — 사용자가 인식 실패로 오해한다)
- [ ] 쓰기 방지 USB는 보이되 **"쓰기 금지 상태"**로 선택 불가
- [ ] 목록에 넣지 못한 장치가 있으면 **그 이유가 목록 아래에 적힌다**
      ("목록에 넣지 못한 장치가 있습니다:" — 카드 없는 리더, 조회 실패 등.
      아무 말 없이 사라지면 사용자는 프로그램이 USB를 못 봤다고 읽는다)

## 2. 권한

- [ ] 관리자 권한 없이 실행하면 UAC 창이 뜬다
- [ ] UAC를 거부하면 이유를 설명하고 종료된다 (조용히 죽지 않는다)
- [ ] 목록 보기까지는 권한 상승 없이도 동작하는지 확인
      (설계상 조회는 권한 0으로 열기 때문에 가능해야 한다)

## 3. 쓰기

- [ ] m-shell로 끝까지 완료된다
- [ ] RR로도 끝까지 완료된다
- [ ] 진행률이 실제로 올라간다 (0%에 멈춰 있지 않다)
- [ ] 각 단계가 순서대로 체크된다
- [ ] 속도와 잔여 시간이 그럴듯하다
- [ ] 완료 화면이 뜬다

### 쓰기 도중 방해하기

- [ ] 쓰는 동안 **탐색기로 그 USB를 열어둔 상태**에서 시작해도 성공한다
      (잠금 재시도가 동작하는지 확인)
- [ ] 취소를 누르면 **실제로 멈춘다** (화면만 바뀌는 게 아니다)
- [ ] 쓰는 도중 USB를 뽑으면 오류가 뜨고, USB가 불완전하다고 알려준다
- [ ] **준비 단계에서 실패했을 때** — 쓰기가 시작되기 전에 USB를 뽑아 재현한다 —
      "USB를 준비하다 중단됐습니다"와 함께 **이미 지워졌다는 사실**과 다시 시도하는
      방법이 나온다. "탐색기를 닫고 다시 시도하세요" 처럼 USB가 멀쩡하다는 전제의
      안내가 나오면 안 된다 (그 USB는 이미 비어 있어 탐색기에 뜨지도 않는다)
- [ ] 실패 문구에 **어느 단계에서, 어디에서 멈췄는지**가 함께 나온다

`device/windows/` 는 자동 테스트가 없는 층이다(README 「테스트가 닿지 않는 곳」).
위 두 항목이 그 층에서 사용자에게 나가는 문구를 확인하는 유일한 수단이다.

## 4. 쓰기 이후

- [ ] Windows가 **"디스크를 포맷하세요"**라고 물어본다 → **취소**를 누른다
      (이 대화상자는 정상이며, 앱이 미리 안내해야 한다)
- [ ] USB를 안전 제거할 수 있다 (핸들이 남아 있으면 실패한다)
- [ ] **그 USB로 실제로 부팅된다**
- [ ] 부팅된 로더 화면에서 시놀로지 모델을 고를 수 있다

마지막 두 항목이 이 프로그램의 존재 이유다. 나머지가 다 통과해도 이게 안 되면 실패다.

## 5. 반복 사용

- [ ] 이미 로더가 써진 USB에 **다시 쓰기**가 된다
      (옛 파티션 테이블이 남아 방해하지 않는지 — GPT 백업 헤더 문제)
- [ ] 리눅스 파티션이 있는 USB에도 쓸 수 있다
      (드라이브 문자가 없는 볼륨을 처리하는지)
- [ ] 앱을 껐다 켜도 정상 동작한다

## 6. 검증 기능

검증은 **기본으로 켜져 있다.** 굽기와 복제 두 확인 화면 모두에 체크박스가 있다.

- [ ] 확인 화면에 체크박스가 **켜진 채로** 뜬다 (굽기·복제 양쪽 다)
- [ ] 검증이 통과한다
- [ ] 체크박스를 끄면 검증 단계가 진행 표시에서 빠지고, 완료까지 시간이 절반쯤
      줄어든다
- [ ] 굽기에서 껐다가 시작 화면으로 나갔다 복제로 들어가면 **다시 켜져 있다**
- [ ] 가능하면 **불량 USB**로 시험해 검증이 실패를 잡는지 확인
- [ ] **멀쩡한 USB 가 검증을 통과한다** — 0.4.0 에서 여기가 깨졌다. 되읽기가
      플러시보다 먼저 돌아서, 잘 써진 USB 가 「USB를 준비하다 중단됐습니다 /
      TargetErased { cause: VerifyMismatch }」로 실패했다
- [ ] 검증이 실패했을 때 문구가 **「되읽은 내용이 쓴 것과 다릅니다」** 이고,
      화면에 `TargetErased` 같은 내부 이름이 보이지 않는다

## 7. USB 복제

복제 경로 자체는 CI가 가상 디스크 두 개로 확인한다. 여기 적은 것은 **가상 디스크로는
재현되지 않는 것들**이다 — 진짜 로더가 들어 있는 USB, 탐색기의 개입, 그리고 부팅.

- [ ] 원본으로 로더가 써진 USB를 고르면 **파티션 개수와 복사할 양이 맞게 나온다**
      (32GB USB에 5GB 로더면 5GB 언저리여야 한다. 32GB로 나오면 길이 계산이 틀린 것)
- [ ] 대상 목록에 **원본이 보이지 않는다**
- [ ] 용량이 더 작은 USB를 대상으로 골랐을 때, 복사할 양이 들어가면 허용되고
      안 들어가면 거부된다 (판정 기준은 USB 전체 크기가 아니라 복사할 양이다)
- [ ] 복사 도중 **탐색기가 열리지 않는다** (홀드백이 복제 경로에도 걸리는지)
- [ ] 복제가 끝난 뒤 **원본이 그대로 읽힌다** — 원본은 읽기만 해야 한다
- [ ] 원본과 대상을 **둘 다** 안전 제거할 수 있다 (핸들을 하나라도 흘리면 실패한다)
- [ ] **복제한 USB로 실제로 부팅된다**

마지막 항목만이 최종 확인이다. 바이트가 맞아도 부팅이 안 되면 복제한 것이 아니다.

## 8. 언어

- [ ] 한국어/영어 전환이 즉시 반영된다
- [ ] 영어에서 잘린 문구나 어색한 번역이 없다
- [ ] 시스템 언어가 한국어면 처음부터 한국어로 뜬다

## 9. 배포물

- [ ] Release에서 받은 `.exe`가 **한 파일로 실행된다**
- [ ] WebView2가 없는 환경에서도 실행된다 (부트스트래퍼 동작 확인)
- [ ] SmartScreen 경고가 뜨는지 확인 (코드 서명이 없으므로 뜰 것이다)
- [ ] 파일 크기가 예상 범위인지 (10MB 안팎)

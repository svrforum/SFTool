# USB 복제 (A → B) — 설계

- 날짜: 2026-08-16
- 대상: `XpenologyUsb`
- 상태: 승인됨

## 무엇을 만드는가

이미 로더를 구워 둔 USB(원본 A)를 다른 USB(대상 B)로 복사하는 기능. 로더를 다시
내려받지 않고, 잘 부팅되는 것이 확인된 USB 를 그대로 하나 더 만드는 것이 목적이다.

## 왜 필요한가

지금은 USB 를 하나 더 만들려면 로더를 처음부터 다시 내려받아 구워야 한다. 이미
손에 검증된 USB 가 있는데도 그렇다. 여러 대에 설치하거나 예비본을 만드는 경우
같은 내려받기를 반복하게 된다.

## 결정 사항

두 가지를 사용자와 확정했다.

**복사 범위는 파티션 끝까지.** 32GB USB 에 5GB 로더가 들어 있으면 5GB 만 읽고
쓴다. 전체를 통째로 복사하면 대부분 빈 공간을 옮기느라 13분이 걸린다. 파티션
테이블이 선언한 끝이 곧 의미 있는 데이터의 끝이므로, 그 지점까지만 복사한다.
덤으로 대상 USB 가 원본보다 작아도 내용만 들어가면 된다.

**진입점은 시작 화면의 모드 선택.** 「로더 굽기」와 「USB 복제」 카드 두 장을
보여주고, 이후 단계는 모드별로 갈라진다. 두 흐름이 한 화면에서 섞이면 "대상을
먼저 고르고 원본을 나중에 고르는" 헷갈리는 순서가 되기 때문이다.

## 설계의 핵심

**원본 USB 를 `Read` 스트림으로 감싼다.** 그러면 로더를 굽는 파이프라인이 그대로
재사용된다.

```
로더 굽기:  네트워크 → gzip 해제 → [Read] → 쓰기 루프 → 장치
USB 복제:   원본 USB           → [Read] → 쓰기 루프 → 장치
                                    ↑
                              같은 코드
```

이것이 중요한 이유는 쓰기 루프가 이미 비싸게 배운 것들을 담고 있기 때문이다.

- **홀드백** — 이미지 맨 앞 1MiB 를 들고 있다가 맨 마지막에 쓴다. 파티션 테이블이
  먼저 장치에 닿으면 윈도우가 쓰는 도중에 볼륨을 마운트해 버리고, 그때부터 쓰기가
  거부되며 탐색기가 "드라이브를 검사하고 수정하세요" 를 띄운다. 실제로 겪었다.
- 섹터 배수 정렬과 패딩(남는 부분을 명시적으로 0으로 채우기 — 안 그러면 힙 내용이
  USB 에 실린다)
- 쓰면서 SHA-256 을 쌓아 두고, 검증 시 되읽은 것과 대조
- 용량 초과 검사, 취소 확인, 진행률 보고
- 꼬리 0으로 덮기 (옛 GPT 백업 헤더가 살아나지 않도록, 방금 쓴 이미지는 침범하지
  않는 범위에서)

복제 경로에서 이 버그들을 처음부터 다시 만날 이유가 없다.

## 구조

### 새로 만드는 것

| 파일 | 책임 | 의존 |
|---|---|---|
| `core/layout.rs` | 디스크 앞부분 바이트 → 복사할 길이. 순수 함수 | 없음 |
| `core/sink.rs` | 스트림 → 장치 쓰기 루프 (지금 `runner.rs` 안에 있는 것) | `WriteSession` |
| `core/cloner.rs` | 복제 파이프라인 | `layout`, `sink`, `safety`, `RawReader` |
| `device/*`: `RawReader` / `ReadSession` | 읽기 전용 세션 | — |

### 고치는 것

- `core/runner.rs` (795줄) — 쓰기 루프를 `sink.rs` 로 옮긴다. 복제와 무관하게도
  필요한 정리다.
- `core/safety.rs` — 복제용 규칙 추가
- `src/commands.rs`, `src/lib.rs` — 새 명령 등록
- `src/main.ts` — 모드 선택 화면 + 복제 흐름
- `device/fake.rs` — 가짜 원본
- `tests/vhd_write.rs`, CI — VHD 두 개로 실제 복제 시험

### `core/layout.rs`

```rust
pub enum Scheme { Mbr }

pub struct Layout {
    /// 복사해야 할 바이트 수. 마지막 파티션이 끝나는 지점.
    pub bytes: u64,
    pub scheme: Scheme,
    /// 확인 화면에 보여줄 파티션 개수.
    pub partitions: u32,
}

pub enum LayoutError {
    NoSignature,      // 0x55AA 가 없다
    NoPartitions,     // 테이블은 있는데 항목이 전부 비었다
    Gpt,              // GPT 다 — 지금은 지원하지 않는다
    BeyondDevice { need: u64, have: u64 },  // 테이블이 장치 밖을 가리킨다
}

/// `head` 는 장치 맨 앞에서 읽은 바이트. GPT 헤더가 LBA 1 에 있으므로
/// **최소 2 섹터**가 필요하다. `device_bytes` 는 장치 크기.
pub fn parse(head: &[u8], device_bytes: u64, sector: u32) -> Result<Layout, LayoutError>;
```

MBR 항목 4개를 훑어 `max(시작 LBA + 섹터 수)` 를 구한다. 확장 파티션(0x05/0x0F)이
있어도 그 항목 자체가 논리 파티션 전체를 덮으므로 같은 계산으로 맞는다.

**GPT 는 거부한다.** LBA 1 의 `EFI PART` 서명으로 감지한다. GPT 백업 헤더는 디스크
맨 끝에 있어서, 크기가 다른 USB 로 옮기면 헤더 위치·`AlternateLBA`·`LastUsableLBA`
와 CRC 를 다시 계산해 줘야 한다. 그걸 조용히 틀리면 부팅은 되는데 나중에 깨지는
종류의 버그가 된다. m-shell·RR 로더는 MBR 이므로 실제로 막힐 일이 없고, 막히는
사용자가 나오면 그때 제대로 만드는 편이 낫다. 보호용 MBR(항목 하나, 타입 0xEE)을
그냥 MBR 로 읽으면 엉뚱한 길이가 나오므로, 감지는 어차피 필요하다.

파티션 테이블이 없는 USB 도 거부한다 — 로더 USB 가 아니라는 뜻이다. "복사할 게
없는데 32GB 를 통째로 옮기는" 것보다 이유를 말하고 멈추는 편이 낫다.

### `device`: 읽기 전용 세션

```rust
pub trait ReadSession: Send {
    fn observed(&self) -> &DiskInfo;
    fn sector_size(&self) -> u32;
    fn total_bytes(&self) -> u64;
    fn read_at(&mut self, offset: u64, buf: &mut [u8]) -> Result<(), DeviceError>;
    fn finish(self: Box<Self>) -> Result<(), DeviceError>;
}

pub trait RawReader: Send + Sync {
    fn open(&self, disk: &DiskInfo) -> Result<Box<dyn ReadSession>, DeviceError>;
}
```

Windows 구현은 `\\.\PhysicalDriveN` 을 **읽기 전용**으로 열고, 공유는 읽기·쓰기
모두 허용하며, **잠그지 않고 마운트를 해제하지 않고 레이아웃을 지우지 않는다.**
쓰기 경로(`raw.rs`)와 파일을 나누어(`device/windows/read.rs`) 원본을 건드리는
코드 경로가 물리적으로 존재하지 않게 한다.

마운트된 볼륨이 있어도 물리 디스크의 읽기는 허용된다. 제약이 걸리는 것은 쓰기뿐이다.

### 스트림 어댑터

```rust
/// ReadSession 을 앞에서부터 `limit` 바이트까지 흘려보내는 Read.
pub struct SessionReader { session: Box<dyn ReadSession>, pos: u64, limit: u64, buf: Vec<u8> }
```

섹터 배수로 읽어 내부 버퍼에 담고, `Read::read` 요청 크기에 맞춰 잘라 준다.
`limit` 에 도달하면 0 을 돌려준다(EOF). 이걸로 원본이 `runner` 의 gzip 스트림과
구별되지 않는다.

### `core/cloner.rs`

```
1. 원본을 읽기 전용으로 연다
2. 신원 확인 (safety::confirm_identity)
3. 앞 1MiB 를 읽어 layout::parse → 복사할 바이트 수
4. safety::can_clone(원본, 대상, 보호 목록, 복사량)   ← 여기까지 대상은 안 건드림
5. 대상을 쓰기용으로 연다 (기존 RawWriter — 레이아웃 삭제·잠금·앞 1MiB 0으로)
6. 대상 신원 확인
7. sink::stream(원본 어댑터 → 대상 세션, 홀드백·해시·진행률·취소)
8. 꼬리 0으로 덮기
9. 검증 (선택)
10. finish
```

4번이 5번보다 앞에 있는 것이 중요하다. 원본을 읽지 못하거나 GPT 라서 거부할 상황에
대상 USB 를 이미 지워 놓으면, 아무것도 못 얻고 멀쩡한 USB 하나를 잃는다.

### 안전 규칙 (`core/safety.rs`)

기존 쓰기 인터록에 더해:

- **원본과 대상이 같은 디스크면 차단.** 디스크 번호와 `identity_key` 둘 다 본다.
- 대상은 기존 쓰기 규칙을 **전부** 통과해야 한다 — USB 버스, 8GB 이상, 시스템/부팅
  디스크 아님, 쓰기 금지 아님, 스팬 볼륨 없음.
- 원본도 같은 목록에서 고른다. 내장 디스크는 애초에 화면에 나타나지 않는다.
- 대상 용량 ≥ 복사할 양.

### 복제 흐름

| 단계 | 화면 |
|---|---|
| 1 | 원본 선택 — 목록, 새로고침 버튼 |
| 2 | 대상 선택 — 원본은 목록에서 빠짐 |
| 3 | 확인 — 방향과 복사량, 검증 체크박스 |
| 4 | 복사 — 진행률, 취소 |
| 5 | 완료 — 요약, 안전 제거 버튼 |

확인 화면은 어느 쪽이 지워지는지가 한눈에 들어와야 한다.

```
   원본 (읽기만)                    대상 (전부 지워짐)
   SanDisk Ultra 32GB      →       Samsung BAR 64GB
   MBR · 파티션 3개                  ⚠ 이 USB 의 내용은
   복사할 양 4.98 GB                   모두 사라집니다
```

검증은 굽기와 동일하게 기본 꺼짐, 체크박스로 제공한다.

### Tauri 명령

- `analyze_source(disk_number) -> SourceInfo { bytes_to_copy, scheme, partitions }`
  — 확인 화면에서 복사량을 먼저 보여주기 위한 것. 원본만 읽고 대상은 건드리지 않는다.
- `clone_start(source, target, verify)` — 진행률은 기존 이벤트 채널 재사용
- `list_disks`, `cancel`, `eject` 는 그대로 재사용

한국어·영어 문자열을 기존 i18n 표에 추가한다.

## 검증

하드웨어 없이 확인되는 것:

- `layout.rs` — MBR 픽스처. 정상 3파티션, 빈 테이블, 서명 없음, GPT 보호 MBR,
  장치 밖을 가리키는 항목, 확장 파티션, 512/4096 섹터
- `safety.rs` — 같은 디스크 선택, 용량 부족, 원본이 시스템 디스크, 대상이 쓰기 금지
- `sink.rs` — 홀드백 순서(기존 `runner` 테스트를 여기로 옮긴다), 패딩, 취소, 용량 초과
- `cloner.rs` + `fake.rs` — 가짜 원본 → 가짜 대상 전체 파이프라인. 원본 바이트와
  대상 바이트가 같은지. **분석에 실패하면 대상에 쓰기가 한 번도 일어나지 않았는지**
- `SessionReader` — 부분 읽기, 경계, EOF

하드웨어 없이 확인되지 **않는** 것 → VHD CI 잡을 확장한다:

- VHD 두 개를 붙이고, 하나에 MBR 이미지를 쓴 뒤 다른 하나로 복제하고 바이트 비교
- 이미 내용이 있는 대상으로 복제 (재쓰기 경로)

이 프로젝트의 버그는 거의 전부 실행해 봐야 드러났다 — 컴파일도 되고 clippy 도
통과하고 단위 테스트도 초록불인데 실제 장치에서 실패했다. VHD 잡이 그 왕복을 끊는다.

여전히 실물이 필요한 것: USB 버스 타입 판정, 실제 USB 컨트롤러 전송 특성,
`CM_Request_Device_Eject`, 그리고 복제한 USB 가 실제로 부팅되는지.

## 하지 않는 것

- GPT 원본 복제 (감지해서 거부)
- 원본보다 큰 대상의 남는 공간 활용 (파티션 확장)
- 이미지 파일로 저장하거나 이미지 파일에서 굽기
- 여러 대상에 동시 복제
